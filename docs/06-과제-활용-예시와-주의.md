# 06. 개인과제에 쓰는 예시와 주의할 점

## 예시 1 — 보고서 과제
1. `assignments/01-보고서/초안.md`를 만들고 내가 먼저 초안을 쓴다.
2. Claude 창에 쓴다: `@assignments/01-보고서/초안.md 논리 흐름에서 약한 곳을 찾아 줘. 고쳐 쓰지 말고 이유만 알려 줘.`
3. 지적받은 곳을 **내가** 고친다.
4. 제출 전에 `/assignment-check` 를 실행해 형식·출처 표기를 점검한다(05번 문서의 스킬).
5. commit·push 하고, `AI-사용기록.md`에 한 줄 적는다.

## 예시 2 — 프로그래밍 과제
1. 과제 설명을 `assignments/02-코딩/과제설명.md`에 붙여 넣는다.
2. Claude 창에서 **plan 모드**(먼저 계획만 세우고 파일은 안 고치는 모드)로 바꾸고 쓴다: `과제설명.md를 읽고 어떤 순서로 풀면 될지 계획만 세워 줘.`
3. 계획을 보고 이해가 안 되는 단계는 `/explain-code` 로 설명을 듣는다.
4. 코드는 내가 쓰고, 막히면 오류 메시지를 붙여 넣어 원인을 묻는다.
5. 실행 결과를 확인한 뒤 commit·push.

## 좋은 요청 vs 나쁜 요청
| 나쁜 요청 | 좋은 요청 |
|-----------|-----------|
| 과제 해 줘 | `과제설명.md`의 2번 문제를 풀려면 어떤 개념을 알아야 해? |
| 이거 고쳐 | `analysis.py` 15번째 줄에서 `KeyError`가 나. 왜 나는지 설명해 줘 |
| 보고서 써 줘 | 내가 쓴 서론에서 주장과 근거가 맞지 않는 문장을 찾아 줘 |

요청에 **파일 이름, 원하는 결과, 하지 말아야 할 것**을 넣으면 답이 정확해진다.

## 학업 윤리
- **수업마다 AI 허용 범위가 다르다.** 강의계획서나 교수님 공지를 먼저 확인한다.
- AI를 썼으면 `AI-사용기록.md`에 적고, 요구가 있으면 제출물에 밝힌다.
- Claude가 알려 준 논문·통계·인용문은 **반드시 원문을 찾아 확인**한다. AI는 없는 논문을 그럴듯하게 만들어 낼 때가 있다.
- 내가 설명할 수 없는 코드·문장을 그대로 내지 않는다. 시험이나 발표에서 같은 내용을 물어볼 수 있다.

## 개인정보와 비밀 정보
- 학번·주민번호·전화번호·성적표는 과제 폴더에 두지 않는다.
- API 키나 비밀번호는 `.env` 파일에만 적는다. 이 레포의 `.gitignore`와 권한 설정이 `.env`를 GitHub 업로드와 Claude 읽기에서 막는다.
- 실수로 비밀번호를 커밋했다면 **그 비밀번호를 바로 바꾼다.** 커밋을 지워도 기록에 남는다.
